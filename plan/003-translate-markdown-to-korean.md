# Markdown 문서 한국어 번역

- **상태:** 완료

## 동기

저장소의 사용자 문서와 작업 규칙 문서 일부가 영어로 작성되어 있어 한국어 사용자가 프로젝트 구조와 개발 절차를 일관되게 이해하기 어렵습니다.

## 목표

영어로 작성된 모든 Markdown 문서의 설명, 제목, 표, 목록을 자연스러운 한국어로 번역하면서 기술 식별자와 실행 가능한 예시는 변경하지 않습니다.

## 범위

- `AGENTS.md`와 영어로 작성된 `docs/` 문서 5개를 번역합니다.
- 계획 및 작업 로그 템플릿과 `001`, `002`의 과거 계획 및 작업 로그를 번역합니다.
- 이 계획의 영문 구조 표기와 상태도 번역된 작업 규칙에 맞게 정리합니다.
- 코드 블록, 명령어, 파일 경로, URL, 환경변수, 클래스·함수·모듈명, 제공자와 라이브러리 고유명은 그대로 유지합니다.
- 이미 한국어 중심인 `README.md`와 `docs/CODE_GUIDE.md`는 제외합니다.
- Python 코드와 런타임 동작은 변경하지 않습니다.

## 단계

1. 작업 규칙, 개발 문서, 아키텍처와 제공자 문서를 의미와 링크를 보존해 번역합니다.
2. 계획 및 작업 로그 규칙과 템플릿의 대응되는 제목·필드·상태 용어를 일관되게 번역합니다.
3. 과거 계획 및 작업 로그와 현재 계획을 동일한 용어 체계로 번역합니다.
4. 링크, 코드 블록, 명령어, 경로와 기술 식별자가 유지됐는지 검증합니다.
5. 번역 대상에 영어 설명 문단이 남지 않았는지 확인하고 작업 로그와 계획을 완료합니다.

## 검증

- 대상 Markdown 파일의 한글 포함 여부와 남은 영문 설명을 검색합니다.
- Markdown 제목 구조, 코드 fence 개수, 상대 링크 대상을 확인합니다.
- `git diff --check`를 실행합니다.
- 코드 변경이 없음을 확인하며 문서 전용 작업이므로 `pytest`는 실행하지 않습니다.
